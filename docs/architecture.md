# Architecture

The crates and source files of the desktop app, and the files and folders it keeps.

## Layout

| Crate | What | Notes |
| --- | --- | --- |
| `crates/player-core` | Audio engine | No UI. Symphonia demux + decode, own libopus decoder (`opus.rs`), the system's output behind one `Device` interface (`output.rs`: `system_device`, `devices`): WASAPI on Windows, shared or exclusive (`output/wasapi.rs`, `output/exclusive.rs`; MMCSS "Pro Audio" thread), PipeWire on Linux (`output/pipewire.rs`) with ALSA's default device where there is no PipeWire (`output/alsa.rs`); short fades on pause, seek and stop, gapless (MP4 trim in `mp4gapless.rs`), surround downmix (`downmix.rs`), ReplayGain (`replaygain.rs`), the equalizer (`eq.rs`: eight kinds of band, up to 32; its presets `eq/presets.rs`, Equalizer APO text read and written `eq/apo.rs`, the other formats and this app's own `eq/formats.rs`, GraphicEQ curves fitted to bands `eq/fit.rs`), crossfades (`crossfade.rs`; mixed in `engine.rs`, a skip's in `output.rs`), the visualizer's tap and analysis (`spectrum.rs`: the spectrum, its auto level, the waveform) |
| `crates/library` | Library | Folder scan into SQLite, written a batch of album folders at a time (`scan.rs`, `scan/walk.rs`, `scan/batch.rs`; see [Scanning](features/library.md#scanning)), tags (lofty), names taken apart and compared (`names.rs`), which album a track is on (`group.rs`), artists and genres as tables (`relations.rs`), every tag block of a file for View metadata (`meta.rs`, read-only), tag editing's checked writes (`edit/`, see [Tag editing](features/metadata.md#tag-editing)), technical details and their wording (`audio.rs`), art cache, all queries (`query.rs`), smart playlist rules and their SQL (`smart/`; search operators read into rules: `smart/search.rs`), folder watcher (`watch.rs` on `dirwatch.rs`: `ReadDirectoryChangesW` on Windows, inotify on Linux, `dirwatch/`; no polling while every folder is watched) |
| `crates/http` | HTTP | `http-client`: a small blocking client, shared by Last.fm, ListenBrainz, the Subsonic client and the lyrics lookup; WinHTTP on Windows (Windows' own HTTP and TLS: nothing added to the exe; one session per process, its connections kept alive, each request with its own timeouts), ureq with rustls and the system's root certificates on Linux |
| `crates/lastfm` | Last.fm | No UI. Signed API calls over `http-client`, the desktop auth flow, the durable scrobble queue and its thread |
| `crates/listenbrainz` | ListenBrainz | No UI. The API over `http-client` (`api.rs`: the token check, now playing, single and imported listens, recording feedback, the documented limits), the durable listen queue, the account file and the thread with its rate-limit pacing (`submitter.rs`). Feature `mock`: a ListenBrainz stand-in on 127.0.0.1 that checks each request against the documented rules, for the tests and the bench (never in a release build) |
| `crates/subsonic` | Navidrome | No UI, no threads. A blocking Subsonic / OpenSubsonic client over `http-client`: token sign-in (`sign_in`, `Credentials`: the salt and token, never the password), typed reads (`scan_status`, `album_list2`, `album`, `search3`, `cover_art`, `stream`...), writes (`star`, `unstar`, `scrobble`, playlists) each allowed or refused by kind (`Writes`; a read-only client refuses all), errors in classes the app words. Feature `mock`: a Navidrome stand-in on 127.0.0.1 for the app's tests and bench (never in a release build) |
| `crates/md5` | MD5 | RFC 1321, for the two protocols that ask for it: Last.fm's request signatures and Subsonic's password token |
| `crates/discord-ipc` | Discord | No UI, no network. The Discord app's local IPC pipe (handshake, `SET_ACTIVITY`) and the thread that keeps the profile's activity in step |
| `crates/lrclib` | Lyrics online | No UI. LRCLIB lookups (exact, then a strict search), the on-disk answer cache, the debounced lookup thread |
| `crates/ui` | UI, compiled | Compiles `crates/app/ui/*.slint` to Rust; the app uses it as its own (`use marquee_ui::*`). A crate of its own only so that it can be optimized for size (see [Exe size](releases.md#exe-size)) |
| `crates/app` | Slint UI | `ui/*.slint` for markup (compiled by `crates/ui`), `src/` for wiring |

App (`crates/app/src`). The files at the top are the app's core (the window and state,
navigation, playback, the queue, the lists, scanning); each folder is one area, its `mod.rs`
saying what the area is and which file does what:

```
crates/app/src/
  main.rs, state.rs, views.rs, nav.rs, playback.rs, queue.rs, ...  the core (below)
  visualizer/   mod.rs (when it runs, the menu), look, draw, presets, share, beat
  server/       Navidrome: mod.rs (the account's side, when a sync runs), sync, write,
                navidrome (the sign-in), streaming (tracks played as they download),
                streammock (a stand-in server for the tests and the bench)
  playlists/    smart (smart playlists) and smartedit (its editor's draft), file (M3U),
                newplaylist, nameclash
  metadata/     view (View metadata), tagedit (tag editing), details (technical details)
  lyrics/       mod.rs (now playing's lyrics), save (Copy and Save)
  connections/  scrobble (when a play counts; Last.fm), listens (ListenBrainz), presence (Discord)
  tray/         mod.rs (the icon's tooltip, menu and gestures), anim, icon, icon_art
  keys/         map (the bindings as data), shortcuts (running them), edit (Settings > Keys)
  settings/     mod.rs (settings.json), nav (Settings' sections, "Find a setting")
  theme/        mod.rs (theme.toml), accent (the accent following the art)
  platform/     the platform seam: one interface, one implementation per system
  bench/        the measurement harness (the `bench` feature only)
```

- `main.rs` creates the window and state, and `wire` attaches every UI callback.
- `views.rs` fills the page stores (home shelves, album, artist, search, playlists, shelf editor) and handles navigation; `nav.rs` is the back/forward history (unit-tested).
- `playback.rs` glues the queue, the engine and the now-playing UI (`sync_next` keeps the gapless next track in step). `server/streaming.rs` plays the tracks only the server has as they download: the downloader threads, the stream cache and its cap, and `set_client`, the account side's way in (unit-tested against `server/streammock.rs`, a local stand-in for the server's `stream`; see [Streaming](features/lyrics.md#streaming)). Engine events are handled as they arrive. During playback, `ticker.rs` updates progress every 100–500 ms according to the seek bar’s width, or every 100 ms for visible synced lyrics. It stops the idle timer when the window is hidden or fully covered.
- `queue.rs` is pure queue logic (unit-tested).
- `selection.rs` is a list's selection, as data: which rows are chosen, by row keys, a click,
  Ctrl+click, Shift+click and the keys, and moving several rows as one block (unit-tested);
  `selected.rs` is its side in the app: the lists' and the queue's callbacks, what a drag and the
  menu of several tracks act on, and those actions (see [Selecting several tracks](features/navigation.md#selecting-several-tracks)).
- `edition.rs` is which edition runs (portable, installed, AppImage, standalone), the portable checks (`check_writable`) and library folders following the drive (`follow_drive`, with `library::reroot`), `--minimized`; see [Editions](releases.md#editions). `platform/<system>/integration.rs` recognises the edition and holds what touches the system for it: "Start with Windows", the Default apps page, the installer's mutex and quit event.
- `covers.rs` and `rows.rs` are lazy models: covers decode off the UI thread, and only rows on screen ask for them. The newest request is decoded first and requests scrolled long past are dropped. The cache budgets 96 MiB for thumbnails and 16 MiB for full-size covers and blurred backdrops.
- `server/mod.rs` is Settings > Library > Server and when the server's catalog is synced (sign-in, Sync now, Stop, sign-out, what Settings, the sidebar and the pill say); `server/sync.rs` the work on threads of its own (listing the catalog into `library::remote`, the covers of the server's albums); `server/navidrome.rs` the sign-in kept in `navidrome.json`, sealed by `platform::secret` (all unit-tested, the sync against a stand-in server; see [Navidrome](features/navidrome.md#navidrome)).
- `scanning.rs` runs background scans, folder removal and the folder watcher, one job at a time off the UI thread. The start-up scan and Rescan look at everything; what the watcher reports is scanned only where it happened (`library::scan::scopes`). It words a scan's progress (`tell`: what it does, how far, the time left, a slow or stalled disk), carries Stop, and hands what each batch wrote to the open page (`views::library_changed_live`; see [Scanning](features/library.md#scanning)). `activity.rs` decides what the top right of Home shows of a scan or a sync (see "What it says" under [Scanning](features/library.md#scanning)).
- `session.rs` saves and restores the queue and playback position (`library::session`); `placement.rs` the window's size, position and maximized state.
- `search.rs` runs search on its own thread and connection; only the newest query's results are shown. `media.rs` handles media keys and the desktop's media controls (SMTC on Windows, MPRIS on Linux: `platform::media`). `theme/mod.rs` loads the theme file.
- `keys/shortcuts.rs` is the keyboard: it runs the shortcut a key press is bound to (any key the focused control does not take) and says where a list's cursor moves for the arrow and paging keys. `keys/map.rs` holds the bindings as data (each action's default keys, the user's changes from `settings.json`, the fixed keys, conflicts); `keys/edit.rs` is Settings > Keys, the editor. All three are unit-tested. `menus.rs` builds the context menus and the Albums sort menu; `explorer.rs` is "Show in Explorer" (Linux: "Show in file manager").
- `eq.rs` is Settings > Equalizer (the setting per device, presets, copy and paste with their preview, import and export, the curve drawn from the filters; `ui/eq.slint`); `crossfade.rs` the rule of when tracks crossfade (unit-tested; see [Equalizer](features/playback.md#equalizer) and [Crossfade](features/playback.md#crossfade)).
- `output.rs` is Settings > Output (device list, choice, status); `connections/scrobble.rs` when a play counts and what the scrobbling services hear of it (one decision for Last.fm and ListenBrainz), and Settings > Connections > Last.fm; `connections/listens.rs` Settings > Connections > ListenBrainz and a track's listen; `connections/presence.rs` Settings > Connections > Discord and what Discord is told plays; `lyrics/mod.rs` the now playing page's lyrics (local, then online); `visualizer/mod.rs` the visualizer on now playing and its Settings preview (when it runs, the menu, the settings' actions), `visualizer/look.rs` its looks, presets and settings, `visualizer/draw.rs` each style's geometry and brushes, `visualizer/presets.rs` the user's presets (save, rename, update, delete, copy, paste, export, import, the preview before adding), `visualizer/share.rs` a preset as one line of text (all but `visualizer/mod.rs` unit-tested; see [Visualizer](features/visualizer.md#visualizer)); `playlists/file.rs` M3U import and export, `playlists/nameclash.rs` the prompt for a playlist name already in use (import, rename, create); `opener.rs` files from the command line, a second launch and drops from the file manager.
- `autoscroll.rs` is middle-click scrolling (the mode, its speed curve, winit's input hook; unit-tested), with `ui/autoscroll.slint` for the scroll areas' side; `tray/anim.rs` the tray icon's animation, `tray/mod.rs` its tooltip, menu label and what a click, double click, the middle button and the wheel do (both unit-tested).
- `settings/nav.rs` is Settings' sections and its "Find a setting" box (unit-tested); see [Settings](features/settings.md#settings). `zoom.rs` is the interface size: the window's scale factor, its keys, Ctrl and the wheel, a pinch (the ladder, the clamping and the pinch unit-tested; see [Interface size](features/settings.md#interface-size)). `about.rs` is Settings > About and the version (see [About](features/settings.md#about)).
- `playlists/smart.rs` is smart playlists in the app: the thread that works them out, keeping what shows of them up to date, their page and the editor; `playlists/smartedit.rs` the editor's draft and lines (unit-tested; see [Smart playlists](features/navigation.md#smart-playlists)).
- `metadata/details.rs` is "Show technical details" (the playing track's line, the output line, ReplayGain) and a file's details rows; `playlists/newplaylist.rs` the name prompt of "New playlist…"; `metadata/view.rs` "View metadata", with editing in place when tag editing is on, and `metadata/tagedit.rs` the draft, the save thread and the journal's place (all unit-tested; see [Technical details](features/metadata.md#technical-details), [Playlists](features/navigation.md#playlists), [Metadata](features/metadata.md#metadata) and [Tag editing](features/metadata.md#tag-editing)).
- `bench/` is the measurement harness (see [Testing](testing.md#the-bench-runner); only with the `bench` feature): `bench/mod.rs` picks the mode and runs the ones of the first measurements (`grid`, `sidebar`, `tour`, `skip`, `session-*`, `guard`, `idle-*`, `covers`, `playlist`'s timings, `phase4`), and each other file is one subject: `output_devices.rs` output devices, Last.fm, formats, playlist files, lyrics and that no rating is left (`MP_BENCH=phase5`), `player_bar.rs` the auto-hiding player bar, with the queue, sorting, the pill and Settings > Keys (`cleanup`), `visualizer.rs` the visualizer and online lyrics (`visualizer`, `viz-idle`), `settings.rs` the Settings page (`settings`), `autoscroll.rs` middle-click scrolling and the tray icon (`autoscroll`, `tray`), `details.rs` technical details and "New playlist…" (`details`), `metadata.rs` View metadata (`metadata`), `about.rs` Settings > About (`about`), `messy_library.rs` the home page and the messy
  library (`home`, `library`), `editing.rs` tag editing (`editing`), `smart.rs` smart playlists (`smart`), `eq.rs` the equalizer and crossfade (`eq`), `viz_styles.rs` the visualizer's styles, placements and cost (`viz-styles`, `viz-cost`), `bigscan.rs` the first scan of a large library and a long run (`bigscan`, `soak`), `xfade_rates.rs` a crossfade between sample rates (`xfade-rates`), `eq_paste.rs` the equalizer's copy and paste (`eq-paste`), `viz_look.rs` the halo (its ripples and sparks) and the bonfire, the pinned preview, the placement key, opacity and the user's presets (`viz-look`), `server.rs` a Navidrome server against a stand-in it starts itself (`server`), `streaming.rs` tracks streamed from a local mock of the server (`streaming`), `playlist.rs` a playlist's Shuffle and playlist name clashes (`playlist`, after `mod.rs`'s timings), `lyrics.rs` the Lyrics tab's timing, Copy and Save (`lyrics`), `selection.rs` the selection of track lists (the last part of `playlist`), `zoom.rs` the interface size (`zoom`, `zoom-check`), `row_hover.rs` a track row's hover under its play button (`row-hover`), `output_default.rs` the system default output changing (`output-default`, Linux), `listenbrainz.rs` ListenBrainz against a stand-in it starts itself (`listenbrainz`).
- `platform/` is the platform seam: everything the app asks of the system, one interface (`platform/mod.rs`, which lists it), one implementation per system, `platform/windows/`, `platform/linux/` and `platform/macos/`, with what Linux and macOS share in `platform/unix/` (see [Linux](linux.md#linux) and [macOS](macos.md#macos)). Nothing outside it names a system. Windows: `frame.rs` replaces the Windows title bar: the window keeps its native frame (shadow, rounded corners, snap, Alt+Space), but `WM_NCCALCSIZE` gives the caption strip to the app and `WM_NCHITTEST` reports the top resize border and the app-drawn maximize button (`HTMAXBUTTON`, for the Windows 11 snap layouts flyout); `winmsg.rs` subclasses the window and forwards to it; `tray.rs` the tray icon (Slint's, its window subclassed for the buttons, the double click and the wheel hook; see [Tray icon](features/navigation.md#tray-icon)); `instance.rs`, `devwindow.rs`, `placement.rs`, `media.rs` (souvlaki), `shell.rs` (Explorer, the clipboard), `system.rs`, `window.rs` (the hooks), `secret.rs` (DPAPI, sealing the Navidrome token, the Last.fm session key and the ListenBrainz token). Linux: client-side decorations on winit (`window.rs`), a Unix socket for the single instance, MPRIS over zbus, the tray's own StatusNotifierItem through ksni (`tray.rs`), `org.freedesktop.FileManager1`, the XDG directories and the desktop's settings (`system.rs`), a file of mode 0600 for the Navidrome token, the Last.fm session key and the ListenBrainz token (`secret.rs`).
- `tray/icon_art.rs` draws the app icon (a dark navy tile with a sound wave); `build.rs` embeds it as the exe's icon resource, the Windows platform sets it on the window (Win32 `WM_SETICON`), `examples/linux_icons.rs` renders it in the hicolor sizes for Linux (`packaging/linux/make-icons.sh`), `examples/macos_icon.rs` on macOS' icon grid for the bundle's `.icns` (`cargo xtask release`), and `tray/icon.rs` gives the tray the wave alone, drawn at the tray's own size (deeper colours on a light taskbar or a light desktop theme).

UI (`crates/app/ui`): `theme.slint` holds the tokens, `stores.slint` the globals (one per area, plus `Actions` for every callback), `types.slint` the structs they carry, `widgets.slint` the controls, `lists.slint` the lists more than one page shows (the keys every list takes, the cover grid, track lists short and virtualised, the queue) and `vizstage.slint` the visualizer's stage. `pages/` has a file per page (`home`, `browse` for Albums, a shelf's See all, Artists, the groups and Tracks, `album`, `artist`, `search`, `playlists`, `nowplaying`, `shelves`), and `pages/settings/` the Settings page (`settings.slint`) and a file per section. `chrome.slint` is the sidebar, player bar and queue panel, `dialogs.slint` the name prompt and the panel the dialogs share, `metaview.slint` View metadata, `smart.slint` smart playlists, `eq.slint` the equalizer, and `app.slint` the window and tray. `crates/ui/build.rs` compiles `app.slint`; Slint follows its imports and has Cargo rebuild when any file it imported changes.

| --- | --- | --- |

| Theme tokens (hot-reloaded) | `%APPDATA%\MarqueePlayer\theme.toml` | `~/.config/marquee-player/theme.toml` |
| Library database (plays, favourites, playlists and smart playlists' rules, the saved queue, each track's technical details and tags, artists and genres, a scan to pick up) | `%APPDATA%\MarqueePlayer\library.db` | `~/.local/share/marquee-player/library.db` |
| Log (started afresh at every start of the instance that runs, the previous run's kept beside it as `marquee-player.previous.log`; a second launch that only hands over its files leaves both alone; its first line is the version and the system; each line has the seconds since the start) | `%APPDATA%\MarqueePlayer\marquee-player.log` | `~/.local/state/marquee-player/marquee-player.log` |
| Tag editing's undo journal (`saves`, `pictures`) and the records of writes under way (`inflight`) | `%APPDATA%\MarqueePlayer\edits` | `~/.local/share/marquee-player/edits` |

| ListenBrainz's server address, user name and token, the token sealed with DPAPI for the current Windows user (`listenbrainz.json`); listens not yet sent (`listens.json`); Disconnect keeps only the server address | `%APPDATA%\MarqueePlayer` | `~/.local/share/marquee-player` (`listenbrainz.json` mode 0600) |
| The Navidrome sign-in (`navidrome.json`: the address, the user, what the server is, and the salt and token sealed with DPAPI for the current Windows user; never the password; deleted by signing out) | `%APPDATA%\MarqueePlayer` | `~/.local/share/marquee-player` (the file mode 0600) |
| Each track's lyrics timing offset (`lyrics-offsets.json`: the track's path and milliseconds, only those not 0) | `%APPDATA%\MarqueePlayer` | `~/.local/share/marquee-player` |
| Art cache (safe to delete; rebuilt by the next scan) | `%LOCALAPPDATA%\MarqueePlayer\art` | `~/.cache/marquee-player/art` |
| Lyrics found online, and "not found" answers; the server's lyrics of its tracks (`lyrics\server`) (safe to delete; looked up again as tracks play) | `%LOCALAPPDATA%\MarqueePlayer\lyrics` | `~/.cache/marquee-player/lyrics` |
| Tracks from the server, kept to play again: one file per song, a `.partial` sidecar beside one still downloading (capped at 2 GB by default, Settings > Playback; safe to delete; cleared on sign-out; see [Streaming](features/lyrics.md#streaming)) | `%LOCALAPPDATA%\MarqueePlayer\stream` | `~/.cache/marquee-player/stream` |

On Linux these follow the XDG base directory specification: `$XDG_CONFIG_HOME`,
`$XDG_DATA_HOME`, `$XDG_STATE_HOME` and `$XDG_CACHE_HOME` replace `~/.config`,
`~/.local/share`, `~/.local/state` and `~/.cache` when set to absolute paths (`paths.rs`,
`platform::system::app_dirs`). `MP_DATA_DIR` puts everything in one folder on both, as the
portable edition does in its `Data` folder (Windows) or the AppImage's `.home` folder (Linux;
see [Editions](releases.md#editions)).

On macOS everything above is in `~/Library/Application Support/MarqueePlayer`, the caches
(art, lyrics, stream) in `~/Library/Caches/MarqueePlayer` ([macOS](macos.md#what-is-different-on-macos)).

`theme.toml` is written with every token on first start. Save it and the window
updates. A partial file is fine: missing keys keep their defaults.
